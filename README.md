# OmniCorp SmartSearch

A RAG (retrieval-augmented generation) chatbot for OmniCorp **Customer Success Managers**. Ask a question about
internal documentation and get an answer that is **grounded only in the knowledge base**, with **validated
citations** to the exact document and chunk. If the docs don't cover the question, the bot says so instead of
guessing.

![stack](https://img.shields.io/badge/stack-NestJS%20·%20React%20·%20OpenAI-4f46e5)

## Features

- Ingests Markdown knowledge-base articles from [`source/`](source/) (5 sample articles included).
- Markdown-aware chunking, OpenAI embeddings, in-memory vector store, cosine similarity search.
- Answers generated by `gpt-4.1-mini` with strict grounding rules and structured JSON output.
- **Citation validation:** every cited chunk id must be one that was retrieved for that question. Invented ids are
  dropped; if no valid citation remains, the answer is refused.
- **Refusal** when nothing relevant is found (no LLM call is made) or when the model says the docs don't answer.
- Responsive React + Tailwind chat UI with the OmniCorp logo, numbered source cards and a documents panel.
- Security: DTO validation, rate limiting, helmet, CORS, uniform error responses, and the API key stays in the backend.
- Automated tests: backend unit + e2e (no network, fake AI providers) and frontend component tests.

## Architecture at a glance

```
Browser ──► frontend (nginx: React SPA, proxies /api) ──► backend (NestJS) ──► OpenAI API
                                                            │

                                                            └─ in-memory vector store
```

## Quick start (Docker Compose)

Prerequisites: Docker with Compose v2, and an OpenAI API key.

```bash
cp backend/.env.example backend/.env      # then set OPENAI_API_KEY in backend/.env
cp .env.example .env                      # optional: change ports
docker compose up --build
```

- Chat UI: <http://localhost:8080>
- API: <http://localhost:3000/api> · Swagger: <http://localhost:3000/api/docs>

The backend loads and embeds the knowledge base on startup. `GET /api/health` shows progress
(`knowledgeBase.status`: `loading` → `ready`).

## Running locally without Docker

Requires **Node.js 22** (`nvm use` reads [`.nvmrc`](.nvmrc)).

```bash
# Terminal 1 — backend on :3000
cd backend
cp .env.example .env    # set OPENAI_API_KEY
npm install
npm run start:dev
```

```bash
# Terminal 2 — frontend on :5173 (proxies /api to :3000)
cd frontend
npm install
npm run dev
```

## Configuration

All backend settings are environment variables, validated at startup (the app fails fast and lists the bad keys,
never their values). See [`backend/.env.example`](backend/.env.example).

| Variable | Default | Purpose |
| --- | --- | --- |
| `OPENAI_API_KEY` | — (required) | OpenAI credential. Backend only. |
| `OPENAI_CHAT_MODEL` | `gpt-4.1-mini` | Answer generation model |
| `OPENAI_EMBEDDING_MODEL` | `text-embedding-3-small` | Embedding model |
| `SOURCE_DIR` | `../source` | Knowledge-base folder (Docker: `/app/source`) |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `800` / `120` | Chunk size and overlap, in characters |
| `TOP_K` | `5` | Chunks retrieved per question |
| `MIN_SIMILARITY` | `0.3` | Cosine floor; below it the question is refused without an LLM call |
| `CORS_ORIGIN` | `http://localhost:5173` | Allowed browser origins (comma-separated) |
| `CHAT_RATE_LIMIT_PER_MIN` | `20` | Requests per minute per client on `/api/chat` |
| `LOAD_DOCUMENTS_ON_STARTUP` | `true` | Ingest the knowledge base at boot |

The frontend has **no secrets**. It always calls the relative path `/api`. `VITE_PROXY_TARGET` (dev only) tells Vite
where to proxy it.

## API

Full reference: [docs/api.md](docs/api.md).

```bash
# Ask a question
curl -s -X POST http://localhost:3000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"question":"What is the first response time for a Severity 1 incident on Premium?"}'
```

```json
{
  "answer": "Premium customers get a first response within 1 hour, 24/7, for Severity 1 incidents [sla-and-support-tiers#3].",
  "citations": [
    {
      "sourceId": "sla-and-support-tiers",
      "documentTitle": "SLA and Support Tiers",
      "chunkId": "sla-and-support-tiers#3",
      "textSnippet": "First response targets are measured from ticket creation to the first human reply. …"
    }
  ],
  "refused": false
}
```

```bash
curl -s -X POST http://localhost:3000/api/documents/reload   # re-read source/, re-chunk, re-embed
curl -s http://localhost:3000/api/documents                  # document metadata table
curl -s http://localhost:3000/api/health                     # liveness + knowledge-base status
```

## Adding or changing documents

1. Put `.md` files in [`source/`](source/). An optional front-matter `title:` sets the display title; otherwise the
   first `# Heading` is used.
2. The file name becomes the `sourceId` (for example `billing-and-refunds.md` becomes `billing-and-refunds`). Keep file names stable, because
   citations reference them.
3. Call `POST /api/documents/reload` or press **Reload** in the UI. In Docker the folder is mounted read-only, so no
   rebuild is needed.

## Tests

No test calls OpenAI. Deterministic fake providers replace the embedding and chat models.

```bash
cd backend && npm test && npm run test:e2e && npm run lint && npm run typecheck
cd frontend && npm test && npm run lint && npm run typecheck
```

Without Node 22 installed, run the same suites in Docker:

```bash
docker build --target test -t smartsearch-backend-test backend && docker run --rm -v "$PWD/source":/source:ro smartsearch-backend-test
```

```bash
docker build --target test -t smartsearch-frontend-test frontend && docker run --rm smartsearch-frontend-test
```

| Suite | Covers |
| --- | --- |
| Backend unit | chunker, loader, vector store, citation validator, chat pipeline, reload service, env validation, prompt escaping, OpenAI error mapping |
| Backend e2e | all endpoints over HTTP: reload stats, documents list, grounded answer, refusals, hallucinated-id rejection, 400/502/503 errors, request ids |
| Frontend | chat flow, citations, refusal and error states, input validation, documents table and reload, API client |

## Security notes

- `OPENAI_API_KEY` exists only in `backend/.env` (gitignored). It is never logged, returned or bundled into the frontend.
- Requests are validated with class-validator DTOs: unknown fields are rejected, `question` must be 3–1000 characters, and the body is capped at 16 KB.
- Errors use a uniform body: `{statusCode, error, message, path, timestamp, requestId}`. Provider failures are
  mapped to safe 502/503/504 messages.
- Retrieved document text is treated as untrusted data in the prompt (delimited and escaped) to reduce prompt-injection risk.
- `/api/chat` is rate-limited. Responses use helmet headers, and nginx adds a strict CSP to the UI.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Backend exits with `Invalid environment configuration` | Set the listed variables in `backend/.env` |
| Chat returns 503 "knowledge base is not loaded" | Wait for startup ingestion, or check `GET /api/health` and the backend logs |
| 502 "AI provider rejected the backend credentials" | `OPENAI_API_KEY` is wrong or revoked |
| Everything is refused | Lower `MIN_SIMILARITY` slightly (for example `0.25`) and check that the documents loaded |
| `git` fails with an Xcode license error (macOS) | Run `sudo xcodebuild -license accept` |
